# OpenAll (кратко по-русски)

**Изучение скомпилированной Windows-программы с Claude: сначала факты на полочках, потом смысл, ничего непроверенного.**

> Статус: **v0.3.0, кандидат в релиз / прототип.** Описанный ниже режим «полочек» проверен на четырёх маленьких
> программах, которые мы написали сами. Прочитай «Что проверено» и «Известные ограничения», прежде чем на него
> полагаться. Прочитай [DISCLAIMER.md](DISCLAIMER.md): изучай только свои программы, программы с разрешением
> владельца или то, что разрешает закон.

## Что он делает

Для Windows x64 `.exe`/`.dll` проект отделяет **факты** от **толкования**:

1. **Полки 0-2 (факты, делают скрипты):** `scripts/build_shelves.py` перечисляет функции, граф вызовов, строки,
   импорты, данные, таблицы виртуальных функций (с именами классов, если они есть в файле), обработчики исключений и
   таблицы `switch`. Модель здесь не участвует, ничего не угадывается. Код компилятора и библиотек узнаётся по
   *наборам эталонов* (хеши маленьких программ, собранных тем же компилятором), поэтому остаётся в основном свой код.
2. **Полка 3 (смысл, пишет Claude):** по короткой странице на каждую свою функцию, снизу вверх, по заданию-пакету.
   Каждое утверждение помечено (`[O]` увидено, `[I]` выведено, `[D]` документация, `[G]` догадка) и ссылается на записи.
3. **Проверяющий:** `scripts/shelf3.py check` отклоняет страницу, если у утверждения нет метки, оно ссылается на
   несуществующую или не относящуюся к функции запись, пропущен вызываемый или похоже на секрет.
4. **Книга:** `scripts/shelf3.py book` собирает личную читаемую книгу и не запускается, пока проверка не пройдена.

Проверяющий доказывает, что утверждения **обоснованы**, а не что они **верны**. Он также не знает, **полна** ли
страница: полноту обеспечивают факты на полках (нераскрытые переходы, обработчики и таблицы там считаются).

## Быстрый старт

1. Windows: распакуй проект, дважды щёлкни `setup_windows.bat` (проверяет Python и 64-битный `g++`, предлагает
   поставить их через winget, всегда спрашивая, собирает три крошечные эталонные программы и выучивает их для твоего
   компилятора). Другие системы: `pip install capstone pefile`, собрать `tests/shelf_demo_cpp/ref_*.cpp` своим
   компилятором и выполнить `python3 scripts/build_shelves.py --learn ref_empty.exe ref_stl.exe ref_numeric.exe`.
2. Положи программу, которую хочешь изучить (64-битный Windows `.exe`/`.dll`, собранный тем же компилятором), в `input/`.
3. Открой папку в Claude Code (или загрузи архив в чат Claude, где можно запускать код) и выполни `/openall-shelves`.
   Ответь на вопрос о законном основании. Книга появится в `workspace/shelves/<имя>/book/`.
4. Нет интернета для `pip`? `pip install --no-index --find-links vendor capstone pefile`.
5. Кончились лимиты на полпути? В чате команда сохраняет `<имя>_progress.zip`: распакуй его в проект и запусти команду
   снова, она продолжит.

Проверить окружение: `python3 scripts/doctor.py`. Запустить тесты: `python3 tests/run_tests.py`.

## Что проверено

Четыре программы, написанные нами (счётчик слов на C; программа с фигурами и виртуальными классами, калькулятор
выражений и интерпретатор байт-кода на C++), собранные MinGW-w64 GCC 13 (msvcrt) и GCC 16.2 (UCRT, WinLibs), без символов.

| Проверка | Результат |
|---|---|
| Счётчик слов на C, 165 функций | ровно 2 своих функции остались «своими»; страницы совпали с исходником |
| Слепой тест: калькулятор (исходник модель не видела) | 9 страниц и обзор, все утверждения совпали с исходником |
| Слепой тест: интерпретатор байт-кода (исходник модель не видела) | 23 страницы и обзор; всё совпало; предсказанный вывод программы и CRC точные |
| Автотесты (`tests/`) | 13 тестов: правила проверяющего, порядок, рекурсия, проверка построителя |

Оценку сделал сам помощник проекта по сравнению с исходным кодом, а не независимый рецензент. Подробности, цифры и все
найденные по дороге ошибки: [docs/FORMAT.md](docs/FORMAT.md) (разделы 8.1-8.9).

## Известные ограничения

- **Только Windows PE x64.** Нет 32-бит, .NET, ELF, Mach-O, Android.
- **Проверялись только сборки GCC (MinGW-w64).** MSVC и clang не проверялись. Разбор таблиц переходов в стиле MSVC
  написан, но на настоящем выводе MSVC не запускался; таблицы исключений и типовые данные (RTTI) MSVC не читаются.
- **Наборы эталонов привязаны к компилятору и к версии анализатора.** Без набора для твоего компилятора большая часть
  библиотечного кода выглядит как свой, и запуск становится длинным и дорогим. Построитель сам скажет, если набора нет.
- **Шаблонный код C++** (STL), созданный компилятором внутри программы, от своего кода не отличить.
- **Только статический анализ.** Ничего не запускается. Упакованные и запутанные файлы описываются, но не распаковываются.
- **Косвенные вызовы и переходы,** кроме обычных таблиц `switch`, остаются неразобранными и только считаются.
- **Результат зависит от модели,** которая пишет страницы; проверено на одной сильной модели. Названия функций это
  описания модели, а не найденные имена; имена классов берутся из типовых данных, только если они есть в файле.
- **Стоимость.** Маленькая программа (20-30 своих функций) это порядка десятков тысяч токенов; неузнанный
  библиотечный код умножает расход. Пакетные задания держат число раундов небольшим.
- Хук `scripts/guard.py` работает «по мере возможности» и не является границей безопасности.
