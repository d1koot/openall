# COVERAGE - what the clone contains

Written by the Analyst at the start (plan) and updated by the Builder/Verifier (result).
Status values: `built` | `stub` (UI present, function replaced by a placeholder) | `missing-input` (not possible
from what was provided) | `out-of-scope` (server, DRM, accounts, proprietary engine).

| Feature | Status | Why / what would be needed |
|---|---|---|
| <feature> | built | seen in UI and readable resources |
| <feature> | stub | logic is inside native code that was not provided |
| <feature> | missing-input | needs the repo/module that was not sent |

## Summary for the user (3-5 lines, plain language)
- What the clone can do now.
- What is stubbed or missing and why.
- What to provide to get more (repo folder, more files, screenshots, test data).
